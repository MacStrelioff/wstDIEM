Venice key-management experiment

Transferable wstDIEM key dashboard prototype

This section demonstrates server-side Venice ADMIN key handling and per-address INFERENCE key limits. It is not the live contract dashboard: users call Venice directly with limited keys, while the backend patches or revokes key limits from a wstDIEM balance source. The server-side Venice ADMIN key remains server-only. Contract-staked DIEM attribution still needs Venice-side proof before this becomes production key automation.

Use this as a key-management prototype. The actual deployed Base contracts and verified transactions are in the Live Base MVP section below.

Live Base MVP

Real wstDIEM contracts are deployed on Base

The live contract flow has been tested with dust DIEM: approve DIEM, deposit into the vault, vault stakes DIEM through the upstream DIEM contract, vault mints non-transferable wstDIEM, then redemption burns wstDIEM and initiates DIEM's 24-hour cooldown. Venice API key automation is intentionally not live yet because contract-staked DIEM attribution still needs Venice-side proof.

Live state is read from Base. Connect a wallet to transact, or refresh to read public vault state.
